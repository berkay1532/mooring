# D3-B — Mooring Web App Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship `apps/web`, the owner-facing Mooring web app: connect Freighter, see all cards in a centered 3D carousel (or a list), create cards through a 3-step wizard, fund them, and run every owner operation with one consistent transaction-status flow, in the landing page's night-harbor design language, deployed to Vercel.

**Architecture:** Next.js 15 (App Router, TypeScript, Tailwind 4) with no server component of its own: reads are Soroban RPC simulations from the browser, writes are `AssembledTransaction`s signed by Freighter and submitted from the browser. Contract access goes through generated TypeScript bindings (`packages/contracts-ts`) regenerated from the built WASM. A thin wallet adapter interface (`lib/wallet`) has two implementations: Freighter and a mock used by Playwright. Card discovery is indexer-free (salt probing + add-by-address). UI is a small design system (`components/ui`) plus one `MooringCard` component that the carousel, wizard preview and list thumbnails all reuse.

**Tech Stack:** Next.js `^15.5`, React 19, Tailwind 4 (`@tailwindcss/postcss`), `@stellar/stellar-sdk` exactly `17.0.1`, `@stellar/freighter-api` `^6.0.1`, `@tanstack/react-query` `^5`, `qrcode` (SVG QR), vitest + React Testing Library, Playwright, `stellar` CLI 26 for bindings, Vercel.

**Spec:** `docs/superpowers/specs/2026-09-13-d3-web-app-design.md` (all sections except §3.6, delivered by D3-A). Visual references (approved mockups): `docs/superpowers/specs/mockups/2026-09-13-cards-carousel-f2.html` and `docs/superpowers/specs/mockups/2026-09-13-wizard-and-tx.html` — open them in a browser; implementers copy their layout, spacing and treatment.

## Global Constraints

#!/usr/bin/env bash
# Regenerates TypeScript bindings from the built wasms. Run `make build` first.
set -euo pipefail
cd "$(dirname "$0")/.."
ROOT=$(cd ../.. && pwd)
for c in card factory; do
  stellar contract bindings typescript --wasm "$ROOT/target/wasm32v1-none/release/mooring_$c.wasm" --output-dir "/tmp/mooring-bindings-$c" --overwrite >/dev/null
  mkdir -p "src/$c"
  cp "/tmp/mooring-bindings-$c/src/index.ts" "src/$c/index.ts"
done
# The generator pins an old SDK; this package uses the workspace's exact version instead.
echo "bindings regenerated: src/card/index.ts src/factory/index.ts"

### Task 4: Chain layer — derivation, discovery, reads, write builders

**Files:**
- Create: `apps/web/lib/chain/rpc.ts`, `lib/chain/derive.ts`, `lib/chain/discover.ts`, `lib/chain/card.ts`, `lib/prefs.ts`, `test/unit/derive.test.ts`, `test/unit/discover.test.ts`, `test/unit/prefs.test.ts`

**Interfaces:**
- Produces:
  - `saltBytes(n: number) -> Uint8Array` (32 bytes, big-endian counter in the last 4 bytes).
  - `deriveCardAddress(owner: string, salt: Uint8Array, factory: string, networkPassphrase: string) -> string` — `deploySalt = sha256(ownerAddressXdr ‖ salt)` where `ownerAddressXdr = Address.fromString(owner).toScVal().toXDR()`; then contract id = `sha256(HashIdPreimage.envelopeTypeContractId({ networkId: hash(passphrase), contractIdPreimage: fromAddress({ address: factory ScAddress, salt: deploySalt }) }).toXDR())`, StrKey-encoded as a contract.
  - `discoverCards(owner, { rpc, factory, passphrase, max = 32, batch = 8 }) -> Promise<string[]>` — probes `saltBytes(0..)`, checks existence with `rpc.getLedgerEntries(contractInstanceKey(address))`, stops at the first gap; result order = salt order.
  - `verifyOwnedCard(address, owner, ...) -> Promise<CardInfo>` — reads `info()`, throws `Error("This card belongs to another owner")` if `info.owner !== owner`.
  - `lib/prefs.ts`: `getAddedCards(owner)`, `addCard(owner, address)`, `removeCard(owner, address)`, `getSelected(owner)`, `setSelected(owner, address)`, `getViewMode()`, `setViewMode(mode)` — all `localStorage`, all guarded with try/catch, keyed by owner.
  - `lib/chain/card.ts`: `readInfo(address)`, `readMerchants(address)` (wrapping `@mooring/x402-client`'s readers with `config`), and builders using the bindings: `cardClient(address, wallet?)`, `factoryClient(wallet?)` where `wallet` provides `publicKey` and `signTransaction` (Task 5's adapter). Write helpers return `AssembledTransaction`s: `buildCreateCard(params)`, `buildSetLabel`, `buildSetPolicy`, `buildAddMerchant`, `buildRemoveMerchant`, `buildSetSigner`, `buildFreeze`, `buildUnfreeze`, `buildWithdraw`, `buildCancel`, `buildFundTransfer(owner, card, amount)` (USDC SAC `transfer` via `contract.Client.from`-less path: a hand-built `Operation.invokeContractFunction` in a `TransactionBuilder` on the owner's account, simulated with `rpc.prepareTransaction`).
