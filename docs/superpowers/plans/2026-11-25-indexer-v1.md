# Indexer v1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship the week-2 indexer (SOW D2(a)): factory/card/USDC-transfer ingestion into Neon Postgres, a read API, a stellar.expert backfill, and the app's indexer-first discovery, activity feed and merchant-name sync.

**Architecture:** Everything lives in `apps/web` (Next.js 15 route handlers, `runtime = "nodejs"`). `lib/indexer/` holds pure modules behind injected deps (`SqlClient`, `getEvents`, fetchers); route files only wire `createXHandler(deps)`. Reads call `ensureFresh()` so a Hobby plan needs no scheduler beyond the daily cron safety net. Tests run the real SQL on PGlite.

**Tech Stack:** `@neondatabase/serverless` 1.2.1 (`neon(url).query(text, params)`), `@electric-sql/pglite` 0.6.0 (dev), `@stellar/stellar-sdk` 17.4.0 (`rpc.Server.getEvents`, `scValToNative`, `StrKey`), vitest, Playwright.

**Spec:** `docs/superpowers/specs/2026-11-25-indexer-v1-design.md`

## Global Constraints

- Repo language English; branch `feat/indexer-v1` → PR → CI green → merge. Commits end with the attribution lines in CLAUDE.md.
- Never log or echo `DATABASE_URL` / `CRON_SECRET`; `.env.local` stays untracked.
- Read handlers never fail because ingestion failed (serve stale + `X-Mooring-Index-Stale: 1`).
- Bigints never cross a JSON boundary as numbers: amounts are strings in payloads and API responses.
- Every new `NEXT_PUBLIC_*` read must be a literal `process.env.X` (Next inlining); the indexer adds none — `DATABASE_URL`, `CRON_SECRET`, `MOORING_INDEXER_DISABLED` are server-only.
- Addresses validated with `StrKey.isValidEd25519PublicKey` / `isValidContract` before touching the DB.

### Task 2: Normalisers

**Files:**
- Create: `apps/web/lib/indexer/types.ts` — `IndexedEvent = { eventId: string; ledger: number; txHash?: string; ts: string /*ISO*/; contract: string; kind: EventKind | "transfer"; payload: Record<string, string | number | null>; /* for transfer: from, to, amount(string) */ }`, `EventKind` union (spec §3).
- Create: `apps/web/lib/indexer/normalize/rpc.ts` — `fromRpcEvent(e: RpcEventLike): IndexedEvent | null` (symbol topic 0 → kind; `card_created` payload `{owner, card}`; `merchant_*` `{merchant}` from topic 1; `policy_changed` `{expiry, max_per_tx, period_amount, period_duration}`; `state_changed` `{state, stateName}`; `signer_changed` `{signer: hex}`; `label_changed` `{label}`; `withdrawn` `{to, amount}`; `transfer` `{from, to, amount}` handling i128 or map value; unknown topic → null).
- Create: `apps/web/lib/indexer/normalize/stellarExpert.ts` — `fromExpertRecord(r, contract)` (same output, `eventId = "se:" + r.id`, `ts` from `r.ts`), `ledgerOf(id)`, `txOrderOf(id)`.
- Fixtures: `apps/web/test/fixtures/indexer/rpc-events.json` (one of each kind, real base64 captured from testnet), `stellar-expert-card.json`, `stellar-expert-usdc.json` (the two CBI3 rows), `horizon-ledger-txs.json`.
- Test: `apps/web/test/unit/indexer-normalize.test.ts` — every kind decodes; amounts are strings; `ledgerOf("025358062441267201-0000") === 5904134`; unknown topics return null; malformed XDR returns null (never throws).

- [ ] Tests first → implement → pass → commit `indexer: rpc + stellar.expert normalisers`.

### Task 3: Store

**Files:**
- Create: `apps/web/lib/indexer/store.ts` — all SQL in one place:
  `insertCard(sql, {card, owner, factory, createdLedger, createdTx, createdAt, trackedBy})`,
  `knownCards(sql): Promise<Set<string>>`, `applyEvents(sql, events: IndexedEvent[], known: Set<string>)` (routes `card_created` → `insertCard`, card kinds → `card_events`, `transfer` → `payments` with `direction` by which side is a known card; all `ON CONFLICT DO NOTHING`; `label_changed` also updates `cards.label`),

- Test: `apps/web/test/unit/indexer-store.test.ts` on PGlite — apply the fixture events twice (idempotent counts), activity ordering and cursor paging, merchants fold (add → remove → re-add), label upsert, lock acquire/contend/stale-steal.

- [ ] Tests first → implement → pass → commit `indexer: store`.

### Task 4: Tick + freshness

**Files:**
- Create: `apps/web/lib/indexer/tick.ts` — `interface TickDeps { sql: SqlClient; getEvents(req: GetEventsRequest): Promise<GetEventsResponse>; factory: string; usdc: string; now?(): number }`, `buildFilters(factory, usdc)` (spec §2: 4 filters, symbols as base64 XDR), `tick(deps, {budgetMs = 8000, maxPages = 5})` → `{ skipped?: "locked"; pages; events; lastLedger; gap?: { from, to } }`.
- Create: `apps/web/lib/indexer/freshness.ts` — `ensureFresh(deps, maxAgeMs = 20_000): Promise<{ ran: boolean; stale: boolean }>` (never throws; stale = tick threw or was skipped while `last_tick` is older than `maxAgeMs`).
- Test: `apps/web/test/unit/indexer-tick.test.ts` — fake `getEvents` returning pages with cursors; cursor advances and persists; a second concurrent tick is skipped; cursor older than `oldestLedger` → restart from `oldestLedger` with `gap`; budget stops after N pages; unknown-card events dropped, factory-created card then its transfer in the same page applied in order; `ensureFresh` no-op when fresh.

- [ ] Tests first → implement → pass → commit `indexer: tick + ensureFresh`.
